# Executable CLI integration

`run_sealed_probe_parent_ci.sh` is the executable CI entry point for the original
admission CLI and native parent, not another ELF checker. It builds the actual
parent in a fresh protected `/run` directory, then runs `b41_sealed_probe_ci.py`
against explicit independent selected-stock and probe artifacts. The native
parent source and admission CLI are included together; the child now restores
its signal mask and separates provider-copy limits from execution/log limits.
Parent-reported combined CI38049548901 is prerequisite evidence; this new
aggregate executable CLI run has NOT been performed locally.

Invocation from a dedicated root ARM64 Linux CI process (the pinned probe is
AArch64; no x86 loader/emulator substitution or ENOEXEC-as-success):

```sh
CI=true \
TETRIS_B41_SELECTED_STOCK=/absolute/selected-stock-port-assets \
TETRIS_B41_PROBE_ARTIFACT=/absolute/independent-probe-artifact \
TETRIS_CGROUP_PARENT=/sys/fs/cgroup/owned-delegated-ci \
TETRIS_MNL_LAYOUT=vendor/lib64/mt6878/libmnl.so \
sh run_sealed_probe_parent_ci.sh
```

The selected artifact must contain genuine system liblog, all five newly
selected stock Bionic providers and existing vendor libraries. No stale local
root fallback. The explicit libmnl layout is one of the two existing allowed
paths, selected from that artifact's manifest, not guessed by search. The
independent probe must retain the already admitted PROBE_SHA. The existing
producer seals/copies actual source bytes and validates independent constants;
expected hashes are not recomputed from input. No source is reopened in the
native child: the corrected root builder copies retained sealed FDs into its
fresh private tmpfs and makes the root read-only before drop/exec.

The parent supplies a delegated cgroup-v2 directory that ALREADY has the memory
controller in cgroup.subtree_control. This runner never enables controllers or
changes a global/existing group's limit. Per mode it creates a fresh child
cgroup, sets actual memory.max to134217728, and moves only its dedicated
admission process into it before any sealed-source producer/FD exec. The native
adapter independently checks its actual cgroup limit. No boolean proof flag or
fake properties stand in for this. Namespace/mount permissions and root are
required; missing delegation/capability/assets fail, never skip.

First run is actual control, including the existing eight syscall-denial
checks. Only after its parent returns zero, exactly one terminal-reap log marker
and an empty cgroup does the runner admit a separate actual load-only run. Each
admission process FD-execs the existing native parent; that parent exclusively
owns vendor-child wait/reap and all twelve leases. The observer waits only for
that parent, never for the vendor child. Standard streams are replaced by the
existing trusted /dev/null/root-log admission. Pre-handoff Python errors go to
a separate admission log; no pipe/socket is inherited into the native child.

Observation has a30s budget, longer than the existing20s absolute admission/run
plus5s cleanup budget. If it expires, the runner records the parent PID and
retains containment without killing the sole reaper, deleting its code/logs,
releasing its leases or claiming RX stop. Parent remains in quarantine until
actual terminal reap. CI-wide cancellation must contain the complete owned
process group; parent-only forced kill is not valid cleanup evidence.
Catch/report failures preserve their first exception if JSON recording fails.

Code/logs/results remain under the printed protected /run path for parent
artifact collection. Per-mode result JSON is recorded on failures as well.
Final RESULT.json exists only after both actual runs passed; it explicitly
records engine_init_called=false and hardware_readiness=false. Actual probe
output must be the pinned existing LOAD_OK message; no synthetic successful
loader or terminal marker is generated by the runner.

Offline tests (no cgroup writes, native builds, ELF execution or phone):

```sh
PYTHONDONTWRITEBYTECODE=1 python3 test_b41_sealed_probe_ci.py
sh -n run_sealed_probe_parent_ci.sh
```

Build/source/Python dependencies are those enumerated in SEALED_PROBE_PARENT.md,
including the frozen mnl-isolate policy include and pyelftools. New runner uses
only Python standard library. Native root-copy/provider fixtures stay separate;
there is no bind-based copy assumption or root-fixture rewrite here.
INIT remains explicitly excluded: complete configuration/calibration, legitimate
property provenance, modem/CCCI ownership/handshake, mandatory host assistance
responses and actual engine RX shutdown acknowledgement are not supplied by a
load-only CLI result.

## Automated ARM64 gate

The manual `gnss-sealed-load.yml` workflow runs on the official
[`ubuntu-24.04-arm` runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
It downloads only the selected stock artifact from CI38048111345 and the
original load-only probe from CI37898372984. The probe's independent SHA256
is checked before admission; all providers are independently checked while
creating sealed copies. Expired artifacts fail visibly, without a stale-root
fallback or a replacement expected hash.

`ci/gnss-delegated-load.py` bootstraps only its freshly created, named systemd
service. It verifies exact membership and sole-process ownership, moves the
observer into a fresh subgroup, then enables memory only in the newly delegated
subtree. Systemd retains ownership of the service's 256 MiB outer limit; each
actual control/load child has its own 128 MiB limit. This follows systemd's
[cgroup delegation rules](https://github.com/systemd/systemd/blob/main/docs/CGROUP_DELEGATION.md).
No existing/global service or host hierarchy limit changes.

This workflow is destructive CI-only containment, NOT runtime quarantine.
When its main observer exits on timeout/error, or the 90-second service limit
expires, systemd terminates the entire owned process group, including the
quarantined reaper. Any per-mode quarantine marker describes only the state at
observation timeout; it does not survive this outer service cleanup.
`OUTER-CONTAINMENT.json` records that distinction explicitly. This policy must
not be used for hardware-owning runtime or described as terminal vendor reap.
Forced containment is failure, never a successful terminal-reap marker.
Logs, per-mode result JSON and service diagnostics are
collected even when a step fails. Native ARM64 compilation and actual loading
are independent of the x86 compile-only gate in the main CI; neither enables
GNSS on the phone or calls the engine's initialization function.
