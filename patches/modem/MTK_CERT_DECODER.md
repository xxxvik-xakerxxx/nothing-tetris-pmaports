# Bounded MTK certificate decoder

New production `mt6878_md_mtk_cert.c/.h` and `mt6878_md_mtk_fields.asn1`.
Frozen PSS32 backend/header/checker/native fixture/docs/review manifest remain
unchanged. No workflow, package, config, DT, phone or git operations.

## Exact authenticated construction

Adapted from audited U-Boot `bffec9306e7c40a432d79deefb450230c2ee2360`,
`board/mediatek/mt6878/tetris_scp_security.c`, using the same
`SEQUENCE OF ANY` grammar and the real kernel ASN.1 engine. The generic engine
walks structure; consumer checks restrict accepted bytes to bounded canonical
DER: certificate <=16KiB, at most48 immediate fields, definite/minimal length
encoding (<=two length bytes), no high tags, no appended bytes, exact SEQUENCE.
Opaque issuer/subject fields are not interpreted as X.509 trust policy; only
the audited security-relevant structure and fields below are used.

Envelope exactly three fields: TBS, exact RSA-PSS/SHA256/MGF1-SHA256/salt32
AlgorithmIdentifier, 256-byte signature BIT STRING with zero unused bits.
Accept only default trailer1 or explicit trailer1. TBS has seven fixed-position
fields followed by OID/value pairs; repeated metadata OIDs and odd pair counts
are rejected. The legacy inner sha256WithRSA label is accepted as an observed
MTK label, never as a PKCS1-v1.5 algorithm selection.

SPKI must have exact rsaEncryption-with-NULL algorithm and a zero-unused-bit
BIT STRING containing canonical RSA2048/exponent65537 public key. Positive
257-byte INTEGER modulus with one leading zero, top-bit-set 2048-bit size and
odd value; exact exponent65537 INTEGER. PSS32 independently validates canonical
270-byte PKCS#1 key before loading raw RSA. No X.509 library/path fallback.

Public `mt6878_md_mtk_verify_header` uses only compiled audited root SPKI DER
SHA256 pin `e1b5235d9411473a358c754f84843801b91f05b8fb9dc4863393e378e41a115e`.
There is no public pin argument. It verifies:

1. Both bounded certificate structures and SPKI/key constraints.
2. Actual root SPKI SHA256 equals compiled pin.
3. Root metadata group1/item2 equals the **entire leaf SPKI DER**, byte-for-byte.
4. Root TBS signature under its own pinned key; leaf TBS signature under its own
   root-delegated key, both through frozen production PSS32. This is the MTK
   delegated-key construction, not ordinary parent-signed X.509.
5. Leaf group2/item6, group2/item8, group4/item2 are exactly observed zero BIT
   STRING transform flags. Header group2/item4 and payload group2/item1 are
   exact32-byte BIT STRING digests, unused bits zero.
6. SHA256 of provided immutable512-byte header matches authenticated header
   digest. Only then copy both authenticated hashes to caller output.

No input pointer is retained. Output is unchanged on any failure, so callers
must consume it only when return ==0, never reuse a previous success after an
error. The function authenticates expected payload hash and header bytes;
**it does not compare actual payload bytes** or grant execution permission.
The bundle consumer still must enforce header magic/member name/length/profile,
all ROM/DRDI/DSP members and signed layout bounds. No anti-rollback or hardware
secure-boot claim is made.

## Ownership / locks

Root and leaf crypto contexts are created once per verification outside supplier
and scope locks; destroyed on all paths, including ERR_PTR constructors. First
decoder/hash/RSA failure is returned; no compensating secure/power operation.
Workspace (certificate tables and two scratch tables) is heap allocated to avoid
large kernel stack frames. Scratch envelope is consumed before SPKI parsing
reuses it; persistent root/leaf body tables are independent. Inputs must remain
accessible and immutable for the entire call. There are no global mutable keys,
internal locks, runtime trust replacement, firmware requests or callbacks.

This does not change the immutable reservation owner or its ENOKEY verdict. No
actual ROM/SMEM mappings/reads, OFF/EMI/remap/NS-access gates or permissions are
modified. Integrate expected-hash preparation before scope; installed-byte checks
remain blocked until the actual gated owner controls mapping, competing writers
and verification/execution lifetime.

## Isolated CI

Local static only:

```sh
python3 patches/modem/check_mtk_cert.py
```

Independent native Ubuntu CI, compiler/libssl-dev/cryptography provisioned by
main; `--kernel` is the pinned Linux source tree:

```sh
CI=true python3 patches/modem/check_mtk_cert.py --native-ci --kernel upstream/linux
```

The checker builds **actual kernel scripts/asn1_compiler.c** with the pinned
kernel's host-tool warning policy, without modifying that upstream tool,
generates the new grammar, and compiles the unmodified actual
`lib/asn1_decoder.c`, generated bytecode, production MTK decoder and frozen PSS32
body with -Wall/-Wextra/-Werror and ASan/UBSan. No mocked DER parser. Linux crypto
API doubles are the frozen PSS fixture's real OpenSSL raw-RSA/SHA256 boundary.
The native shim preserves the kernel fallthrough attribute explicitly.
Kernel logging macro doubles retain format checking without emitting data.

Synthetic tests exercise a private static helper with a synthetic SPKI pin;
the public wrapper is separately required to reject that same chain under its
unchanged real root pin. No production define/runtime API replaces the pin.
Tests cover full cryptographic success and returned hash identities; every
root/leaf truncation; malformed DER, every leaf byte high-bit mutation, field
limit and duplicate OIDs; missing/invalid digest bits; validly signed transformed
profile and wrong delegation; both real signature corruptions; salt64 rejection;
explicit trailer1 acceptance; changed header; all20 hash failure positions and
first error; allocation/raw RSA failure and no partial output/resource leak.

Prepared ARM64 CI kernel, including its host `scripts/asn1_compiler`:

```sh
CI=true CROSS_COMPILE=aarch64-linux-gnu- python3 patches/modem/check_mtk_cert.py \
  --aarch64-object-ci /absolute/path/to/prepared/kernel
```

Temporary external composite object contains production PSS32, MTK consumer and
generated ASN.1 bytecode; real headers, W=1/-Werror, ELF64 AArch64 check. No module
install, modpost, shipping build registration or shared CI edit. Runtime needs
ASN1 decoder, raw RSA and SHA256 algorithms; object compilation alone does not
prove linkage/runtime availability. Native/AArch64 execution pending, no local C
compilation. Stock signed certificates should be the next main-owned CI evidence
after synthetic PASS, without uploading private assets.
